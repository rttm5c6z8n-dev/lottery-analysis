# V3.1 完整追溯与全组合评分

入口仍为 `/personal/`。首页、V17、V28/V29和所有旧研究记录不修改，原V3.0工具在保留区域可继续访问。新库 `lottery_personal_v31` v1，不升级、不清空、不迁移旧库。

## 追溯链

历史快照 `snapshots.id/sourceHash/originalCacheHash/createdAt/throughPeriod` → 训练 `trains.id/trainingTaskId/completedAt/parameters/prepared` → 明确选择的100或300期报告 `reports.id/trainId/snapshotId/sourceHash/version/weightsetId` → 冻结权重 `weightsets.id/reportId/trainId/weights/frozenAt/trainingPeriods/validationPeriods` → 选号任务 `searches.id/config/resultId/reportId/weightsetId/trainId` → 不可覆盖结果 `results.id/searchId/lineage/weights/coverage/picks`。

每阶段都有时间、截止期号、版本和参数。报告必须来自同快照/哈希、同训练、同V3.1版本并已完成，不能以内部30期验证代替100/300期报告。换报告不显示其他报告的选号结果。旧快照缺失字段不回填。新训练/搜索前比较当前原始缓存哈希，变化时要求用户明确重读，不静默套用旧快照。恢复旧任务始终用任务原快照。

## 不改变原评分的全组合搜索

`v31-core.mjs`保留V3.0五模型原始归一化和评分公式，逐号码诊断显示四窗原始次数、遗漏、Z和分母。前后区贡献单独保存；结构是整组前区的奇偶/和值函数，不能伪造单号码结构分。允许号码跨组共享，不排除25、26、05、09。

最终选号通过Pages Function `/api/v31-search` 逐批计算，每批256种前区×全部66种后区。完整遍历324632种前区，显式计算21425712种联合分数，无分层步长、无候选剪枝。每批返回确定性前5、参数摘要、起止游标和真实覆盖率。仅全部完成且事务成功才创建结果，声明全局前5仅针对本研究评分，不是中奖概率。固定数据/参数/版本可复现。

历史回测为手机性能使用精确可加TopK：枚举全部前区，按每个固定模型/权重保留前5，与全部后区交叉。由于总分=A(前区)+B(后区)，前区第6名及以后总有5个不差前区配同后区占优，故不是分层近似。独立策略同分按号码序，不再用融合分干预。单元测试将逐一联合遍历结果与精确可加算法逐项核对一致。

## 云端限制和持久化

现有项目未配置D1/KV/Durable Objects，未假装存在服务器任务库。Pages Function是有界无状态Worker计算；**检查点持久保存在本设备IndexedDB**，不能跨设备续跑。单请求只上传评分系数/权重/源哈希与Top5检查点，不上传原始完整开奖历史；限制32KB和256前区。任务版本/配置SHA256/检查点分数/游标逐项检查。

保持单请求并发，批间隔300ms。一次全量至少1269次请求，真实耗时依网络和Cloudflare限额而定，可能数分钟至更长。429/CPU限额/网络/超时等失败立即停止，保留最近成功覆盖率；无自动无限重试、不虚报100%。选择任务可明确续跑。部分完成只显示覆盖进度，不能标全局完成。

批次进度和最终结果在同一事务写入；验证折与报告/权重集也在同一事务写入，oncomplete后才前移。revision比较拒绝重复/并发提交。只有任务检查点可在本新库更新，快照、权重和结果用add防覆盖。进度保存后刷新可恢复；未提交批次安全重算，不重复计数。

## 权重与验证

100/300期为不重叠的单报告留出集合。校准仅使用该测试开始前最多30个滚动训练折，按一等奖优先、二等奖次之比较预注册6组权重，平局等权；不足10训练折明确未优化。冻结后独立验证，不用验证成绩调参。训练样本还严格限制在该期之前的索引、期号和日期。

每期六策略各5注，随机基线100组各5注，完整记录一二等奖、匹配档位、前后区命中和Wilson近似命中期率区间。样本相同不合并随机重复目标充当独立样本；跨报告的100/300期区间可能重叠，不能并成400期。旧缓存没有当年的发布时间/原始版本证据，仍标“可用性未证实”。已运行独立历史验证不等于已验证预测优势；界面始终明确“未验证预测优势”。
