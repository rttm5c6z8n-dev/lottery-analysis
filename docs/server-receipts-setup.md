# 数理彩研：服务器时间留档（Cloudflare D1）

此功能**尚不能仅凭代码提交投入使用**。需要给承载 `lottery-analysis.pages.dev` 的 Cloudflare Pages 项目连接一套独立的 D1 数据库，并执行表结构迁移。

## 手机端可以完成的部署步骤

1. 登录 Cloudflare Dashboard，进入 **Workers & Pages → D1**，创建专门数据库，例如 `lottery-lock-receipts`。
2. 在新 D1 数据库的 **Console / 控制台** 执行仓库中 `migrations/001_lock_receipts.sql` 的 SQL。确认表 `lock_receipts` 成立。
3. 进入 Pages 项目 **Settings → Bindings → Add binding → D1 database**，变量名必须写 `LOCK_DB`，选择刚创建的数据库。若 Preview 和 Production 环境分别设置，要确保生产环境已连接。Dashboard 菜单名称可能因新版而不同。
4. 重新部署 Pages，让 Functions 接口获得绑定。访问 `/api/lock-receipts?id=invalid`：返回 `BAD_ID` 只是路由存在，不说明数据库绑定已经成功；真正提交前应使用界面的服务器按钮测试。
5. 先在 V4.0 依官方计划核对并锁定未来一期，得到本机 SHA-256 指纹；**开奖前**点击“向服务器提交该期指纹”，接口才会进行再次检查并尝试存进 D1；然后使用“查询服务器留档回执”确认数据可再次取回。

## 安全边界与数据字段

- 服务端仅接收期号、SHA-256 摘要、单注/五注、计划开奖时间；**不会接收7个选号号码**。
- 数据库由服务器记录 `received_at`，首次插入后应用接口只支持只读查询，不提供更新和删除接口。
- 如果 D1 未连接、官网不可用、官网两页最新结果不一致、期号已过、离计划开奖不到一分钟、时间不在下一常规开奖日，均拒绝发回执。
- 回执包含服务器接收时间，是“本服务收到某个哈希摘要”的记录，**不是独立第三方或法定公证**；数据库管理员仍可能修改数据，服务器系统时钟也不是外部可信时间戳机构。为加强证据，可在开奖前将回执及 SHA-256 原始 JSON 凭证另存到独立第三方平台。
- 没有绑定 D1 时，不会伪造已保存、已公证或已发回执的状态。原本在手机上的预测、训练和历史数据不会因此消失。
- 为防止恶意批量提交消耗 D1 配额，正式公开前还需要在 Cloudflare 配置合适的速率限制、滥用防护和保留政策。当前接口适合个人实验，不代表已完成商业级防滥用保护。

`migrations/001_lock_receipts.sql` 是新增表，不应施加到已有 Supabase 或其他项目数据库上。
